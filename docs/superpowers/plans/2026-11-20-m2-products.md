# M2 상품·이미지 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 상품 CRUD, 서버 페이지네이션 목록(검색·필터·정렬, URL 동기화), 상품 이미지 업로드(서버 리사이즈·썸네일, S3 호환 저장소)를 API와 어드민 화면 양쪽에서 완성한다.

**Architecture:**

- API는 `categories`·`products` 모듈과 `storage` 모듈(S3 클라이언트)을 추가한다.
- 상품 생성과 수정은 상품, 재고, 이미지 연결을 한 트랜잭션에서 처리한다.
- 이미지는 먼저 따로 업로드해 미연결 상태로 만들고 상품을 저장할 때 id 목록으로 연결한다.
- 저장소는 S3 API 하나로 통일한다. 로컬과 e2e는 `adobe/s3mock` 컨테이너를, 배포는 Cloudflare R2/S3를 쓴다.
- 브라우저는 Next rewrite `/media/*`를 거쳐 같은 출처에서 이미지를 받는다.
- Web은 FSD 슬라이스(`entities/product`, `features/product-filter`, `features/edit-product`, `features/delete-product`, `widgets/product-table`, `views/product-list`, `views/product-edit`)로 구성한다.

**Tech Stack:**

- 기존: NestJS 12, TypeORM 1.x, PostgreSQL 16, Next.js 16, TanStack Query v5, Zustand, Shadcn UI, RHF + zod, Vitest, Testcontainers, MSW
- 추가: `@aws-sdk/client-s3`, `sharp`, `@types/multer`, `@tanstack/react-table`

**Spec:** `docs/2026-11-20-commerce-backoffice-design.md` (§5 도메인 모델, §8 API 규약·엔드포인트, §9 파일 업로드, §11 프론트, §12 시드), 프로젝트 규칙 `CLAUDE.md`

**선행 조건:** 브랜치 `feat/m2-products`. M0·M1(PR #1) 위에서 시작한다.

**범위 밖 (이후 단계):**

- 재고 수동 조정(`PATCH /products/:id/inventory`, 재고 이력)은 M3로 미룬다. 주문 확정 트랜잭션과 같은 `InventoryHistory`를 공유하기 때문이다. M2에서 재고는 생성할 때 `initialStock`으로만 정한다.
- 엑셀 다운로드는 M5다.
- 일괄 상태 변경과 고아 이미지 정리 크론은 스펙에서 [선택]이라 M6에서 시간이 남으면 한다.

## Global Constraints

- 공통 규칙은 `CLAUDE.md`를 따른다(pnpm 전용, TS ^6.0.3, Vitest 5, FSD 경계, 에러·목록 형식, 커밋 한글). 이 섹션은 M2 고유 값만 적는다.
- 상품 상태: `DRAFT`·`ON_SALE`·`SOLD_OUT`·`HIDDEN`. 라벨은 임시저장·판매중·품절·숨김.
- 금액·재고는 0 이상의 정수다. `price ≤ 100_000_000`, 재고 `≤ 1_000_000`.
- SKU: 대문자 영숫자와 `-`, 3–32자(`/^[A-Z0-9-]{3,32}$/`). 저장 전에 trim하고 대문자로 바꾼다. 삭제되지 않은 상품 사이에서 유일해야 한다(부분 유니크 인덱스).
- 상품명은 1–100자, 설명은 최대 2000자다.
- 삭제는 soft delete(`deletedAt`)다. 삭제된 상품은 목록에서 빠지고, 상세 조회는 404 `NOT_FOUND`다. 삭제된 상품의 SKU는 다시 쓸 수 있다.
- 이미지 업로드:
  - multipart 필드는 `file`, 최대 5MB(`5 * 1024 * 1024`)다. 초과하면 413이다.
  - 실제 형식은 sharp 메타데이터로 판정하고 `jpeg`·`png`·`webp`만 허용한다. 그 밖은 400 `VALIDATION_FAILED`, `details: [{ field: 'file', messages: [...] }]`다.
  - 입력 픽셀 상한은 40,000,000이다. 넘으면 400이다.
  - 원본은 긴 변 최대 1600px webp(quality 82)로, 썸네일은 긴 변 최대 320px webp로 만든다. 둘 다 확대하지 않고(`withoutEnlargement`) EXIF는 제거하되, 회전 정보는 반영한다(`rotate()`).
  - 객체 키는 `products/{yyyy}/{mm}/{uuid}.webp`와 `products/{yyyy}/{mm}/{uuid}_thumb.webp`다.
  - 상품당 최대 10장이다. 이미지가 1장 이상이면 대표 이미지는 정확히 1장이다.
- 이미지 URL은 API가 `/media/{objectKey}` 상대 경로로 내려준다. Web의 Next rewrite가 `/media/:path*`를 `${MEDIA_ORIGIN}/:path*`로 넘긴다.
- 목록 쿼리:

  | 파라미터               | 규칙                                                                                    |
  | ---------------------- | --------------------------------------------------------------------------------------- |
  | `page`, `size`         | `PaginationQuery` 공통                                                                  |
  | `q`                    | 1–50자. `name`·`sku`를 ILIKE로 검색하고, `%`·`_`·`\`는 이스케이프해 글자 그대로 찾는다  |
  | `categoryId`           | uuid                                                                                    |
  | `status`               | 상태 하나                                                                               |
  | `minPrice`, `maxPrice` | 0 이상 정수. `minPrice > maxPrice`면 400                                                |
  | `lowStock`             | `true`면 `quantity <= safetyStock`인 상품만                                             |
  | `sort`                 | `field:dir`. field는 `createdAt`·`updatedAt`·`name`·`price`·`stock`, dir는 `asc`·`desc` |

  기본 정렬은 `createdAt:desc`이고, 같은 값끼리는 `id ASC`로 순서를 정한다.

- 권한:
  - 조회(`GET /categories`, `GET /products`, `GET /products/:id`)는 VIEWER 이상이다.
  - 쓰기(`POST`·`PATCH`·`DELETE /products`, `POST /products/images`)는 MANAGER 이상이다.
- 저장소 환경 변수(api):

  | 변수                   | 기본값                  |
  | ---------------------- | ----------------------- |
  | `S3_ENDPOINT`          | 선택. 비우면 AWS 기본값 |
  | `S3_REGION`            | `us-east-1`             |
  | `S3_BUCKET`            | `bo-media`              |
  | `S3_ACCESS_KEY_ID`     | (필수)                  |
  | `S3_SECRET_ACCESS_KEY` | (필수)                  |
  | `S3_FORCE_PATH_STYLE`  | `true`                  |

  Web은 `MEDIA_ORIGIN`(기본 `http://localhost:9090/bo-media`)을 쓴다.

- 로컬 S3는 `adobe/s3mock`(포트 9090, 버킷 `bo-media`를 `COM_ADOBE_TESTING_S3MOCK_STORE_INITIAL_BUCKETS`로 미리 생성)이고, compose `storage` 프로필에 둔다. **MinIO는 제거한다.** 이 환경에서는 MinIO 이미지를 받을 수 없다.

## Review Focus

1. **형식을 속인 파일과 압축 폭탄**: 확장자만 `.png`인 텍스트 파일, 픽셀 상한을 넘는 이미지, 5MB 초과 파일은 각각 400·400·413으로 거절된다. 저장소에는 아무것도 남지 않는다. → Task 5
2. **이미지 id 재사용과 조작**: 다른 상품에 이미 연결된 이미지, 없는 이미지 id, 대표 이미지 2장, 11장을 보내면 400 `VALIDATION_FAILED`다. 상품·재고·연결은 하나도 저장되지 않는다(원자성). → Task 6
3. **SKU 중복**: `sku-001`(공백·소문자)은 기존 `SKU-001`과 같은 값으로 보고 409 `CONFLICT`, `details: { field: 'sku' }`를 반환한다. soft delete된 상품의 SKU는 재사용할 수 있다. → Task 3, Task 6
4. **조작된 URL 쿼리**: `/products?page=abc&sort=password:asc&status=FOO&minPrice=-1`로 들어와도 화면이 깨지지 않는다. 잘못된 값은 기본값으로 바꿔 API에 보낸다. 반대로 API는 잘못된 `sort`·`status`·`minPrice > maxPrice`에 400을 반환한다. → Task 4, Task 7
5. **검색어의 와일드카드**: `q=50%`나 `q=_`는 모든 상품이 아니라 그 글자를 포함한 상품만 찾는다. → Task 4
