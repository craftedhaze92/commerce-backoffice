# M5 엑셀 다운로드 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**

- 상품 목록과 주문 목록을 **화면에 보이는 필터·정렬 그대로** `.xlsx`로 내려받게 한다.
- 서버는 exceljs 스트리밍으로 응답에 바로 쓰고, 10,000행을 넘으면 파일 대신 422로 필터를 좁히라고 안내한다.
- 핵심은 **목록과 파일이 같은 행을 같은 순서로 담는 것**이다. 필터 로직을 두 벌로 만들지 않고, 실제 DB 테스트로 목록과 파일을 대조한다.

**Architecture:**

- **API**
  - `common/xlsx/`에 도메인을 모르는 엑셀 공용 코드를 둔다: 컬럼 정의 타입, 스트리밍 writer, `Content-Disposition` 생성.
  - `GET /products/export`, `GET /orders/export`는 각 모듈에 둔다. 목록 DTO(`ListProductsQuery`·`ListOrdersQuery`)와 쿼리 빌더(`applyXFilters`·`buildXListQuery`)·행 select를 **그대로** 재사용한다.
  - 건수 확인과 행 읽기는 한 `REPEATABLE READ` 트랜잭션 안에서 한다. 그래야 "10,000행 이하"를 확인한 시점과 파일 내용이 같은 스냅샷에서 나온다.
  - 행은 1,000행씩 나눠 읽어 바로 쓴다(전체를 메모리에 올리지 않는다).
- **Web**
  - `shared/api`에 `httpBlob`을 추가한다. `http`와 같은 CSRF 헤더·쿠키·401 단일 refresh·`ApiError` 정규화를 쓴다.
  - `features/export-excel`의 `ExportButton`이 현재 목록 쿼리 문자열을 받아 다운로드한다. 상품·주문 목록 화면 머리에 붙인다.
- **상태 라벨 이동:** 주문·상품 상태의 한글 라벨을 `@bo/contracts`로 옮긴다. 엑셀(API)과 화면(Web)이 같은 라벨을 써야 하기 때문이다.

**Tech Stack:** 기존 스택에 **exceljs**(apps/api 전용, 설계서 §10이 지정)를 더한다. 그 밖의 새 라이브러리는 없다.

## Global Constraints

- 공통 규칙은 `CLAUDE.md`를 따른다. 이 섹션은 M5 고유 값만 적는다.
- **엔드포인트와 권한:** `GET /api/v1/products/export`, `GET /api/v1/orders/export`. `@Roles(Role.MANAGER)`(권한 맵의 `export:download`). VIEWER는 403, 비로그인은 401이다.
- **쿼리:** 목록 API와 같은 DTO를 받는다. 필터·정렬은 목록과 똑같이 적용하고, `page`·`size`는 받되 무시한다. 잘못된 값은 목록과 같은 400이다.
- **행 수 제한:**
  - `EXPORT_LIMITS = { maxRows: 10_000, batchSize: 1_000 }`(계약).
  - 필터 결과가 `maxRows`를 넘으면 **파일을 쓰기 전에** 422 `EXPORT_TOO_LARGE`, `details: { total, maxRows }`다. 정확히 10,000행은 허용한다.
  - 0행이면 헤더만 있는 파일을 내려준다(에러 아님).
- **스냅샷:** 건수 확인과 모든 배치 읽기는 `REPEATABLE READ` 트랜잭션 하나에서 그 트랜잭션의 `manager`로 한다.
- **시트:**
  - 시트 이름은 `상품`·`주문`이다.
  - 1행은 굵은 헤더이고 틀을 고정한다(`views: [{ state: 'frozen', ySplit: 1 }]`).
  - 금액 셀은 number에 `numFmt: '#,##0'`이다. 수량·재고 셀은 number다.
  - 날짜·시각은 KST 문자열 `YYYY-MM-DD HH:mm`이다(값이 없으면 빈 셀).
  - 사용자 입력(상품명·고객명 등)은 **항상 문자열 셀**로 쓴다. `=`·`+`·`-`·`@`로 시작해도 수식이 되지 않는다.
- **컬럼:**
  - 상품: SKU · 상품명 · 카테고리 · 판매가 · 상태 · 재고 · 안전재고 · 재고부족(`Y`/`N`) · 등록일시
  - 주문: 주문번호 · 고객명 · 상태 · 품목 수 · 주문금액 · 접수일시 · 확정일시 · 취소일시
  - 상태는 한글 라벨(`PRODUCT_STATUS_LABEL`·`ORDER_STATUS_LABEL`, 계약)로 쓴다.
- **응답 헤더:**
  - `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
  - `Cache-Control: no-store`
  - `Content-Disposition: attachment; filename="<ascii>"; filename*=UTF-8''<percent-encoded>` (RFC 5987/6266)
  - 파일명은 `상품목록_YYYYMMDD.xlsx`·`주문목록_YYYYMMDD.xlsx`이고, ASCII 대체 이름은 `products_YYYYMMDD.xlsx`·`orders_YYYYMMDD.xlsx`다. 날짜는 `CLOCK` 기준 KST 오늘이다.
- **스트리밍 중 실패:** 헤더를 보낸 뒤에는 JSON 에러로 바꿀 수 없다. 응답을 끊어(`destroy`) 클라이언트가 불완전한 파일을 성공으로 받지 않게 하고, 서버 로그에 남긴다.
- **Web 다운로드:**
  - 버튼 문구는 "엑셀 다운로드", 진행 중에는 "다운로드 중…"이고 비활성이다.
  - `Can permission="export:download"`일 때만 보인다(VIEWER에게는 숨김. 보안은 서버가 책임진다).
  - 422 `EXPORT_TOO_LARGE`면 `"{total}건은 한 번에 내려받을 수 없습니다. 10,000건 이하가 되도록 필터를 좁혀 주세요."`(role=alert, 숫자는 `toLocaleString('ko-KR')`)를 보인다.
  - 그 밖의 실패는 `"다운로드에 실패했습니다. 잠시 후 다시 시도해 주세요."`다.
  - 파일명은 응답 `Content-Disposition`의 `filename*`를 디코딩해 쓰고, 없으면 `filename`, 그것도 없으면 `export.xlsx`다.

## Review Focus

1. **라우트 가림**: `GET /products/export`가 `GET /products/:id`보다 먼저 매칭돼야 한다. 순서가 틀리면 `ParseUUIDPipe`가 `"export"`를 400으로 막는다. 주문도 같다. → Task 2, Task 3
2. **목록과 파일의 일치**: 같은 쿼리(필터·정렬·KST 기간·검색어)로 목록 API의 모든 페이지를 읽은 결과와 파일의 행이 **같은 순서로 정확히 같다**. 소프트 삭제 상품은 둘 다 빠진다. → Task 2, Task 3
3. **10,000행 경계**: 10,000행이면 파일이 오고 10,001행이면 422 JSON이 온다. 422는 응답 바이트를 하나도 쓰기 전에 결정된다(`Content-Type`이 JSON). → Task 2
4. **한글 파일명과 날짜**: 시각을 2026-11-21 00:30 KST로 고정하면 파일명은 `주문목록_20261121.xlsx`다(UTC로 자르면 20261120). 브라우저는 `filename*`를 디코딩해 한글 이름으로 저장한다. → Task 1, Task 2, Task 4
5. **수식 주입과 셀 타입**: 고객명 `=HYPERLINK("http://x","y")`는 파일에서 문자열 셀이다. 금액은 number이고 `#,##0` 형식이다. → Task 1, Task 2
6. **401 뒤 재시도**: Access 토큰이 만료된 상태에서 누르면 refresh 한 번 뒤 다운로드가 그대로 이어진다(blob 경로도 `http`와 같은 정책). → Task 4

- Create: `apps/web/src/shared/lib/save-blob.ts`(+test), `apps/web/src/shared/api/mocks/export.ts`, `apps/web/src/features/export-excel/{ui/export-button.tsx,ui/export-button.test.tsx,lib/parse-filename.ts,lib/parse-filename.test.ts,index.ts}`
- Modify: `apps/web/src/shared/api/{http-client.ts,http-client.test.ts,index.ts}`, `apps/web/src/shared/testing/msw-server.ts`

**Interfaces:**

- Consumes: `ApiError`, `Can`(entities/session), `EXPORT_LIMITS`·`ExportTooLargeDetails`(계약)
- Produces:
  - `httpBlob(path: string, init?: HttpInit): Promise<{ blob: Blob; contentDisposition: string | null }>`
    - `http`와 같은 `send`·401 단일 refresh·`ApiError` 정규화를 쓴다. 두 함수가 공유하는 부분(전송 + 401 재시도 + 비정상 응답 → `ApiError`)은 내부 함수 하나로 묶고, `http`의 동작은 바꾸지 않는다(기존 테스트 그대로 통과).
  - `parseContentDispositionFilename(header: string | null): string | null`
    - `filename*=UTF-8''…`를 우선 디코딩하고(따옴표·대소문자 무시), 없으면 `filename="…"`, 없으면 null이다. 디코딩에 실패하면 `filename`으로 넘어간다.
  - `saveBlob(blob: Blob, filename: string): void`: object URL을 만들어 숨긴 `<a download>`를 클릭하고 URL을 해제한다.
  - 목: `exportHandlers`. `/products/export`·`/orders/export`가 작은 blob과 `Content-Disposition`(한글 `filename*`)을 돌려준다. `msw-server` 기본 핸들러에 넣는다.
  - `<ExportButton resource="products" | "orders" query={string} />`
    - `Can permission="export:download"`로 감싼다.
    - 누르면 `httpBlob(\`/${resource}/export${query ? \`?${query}\` : ''}\`)`→ 파일명 결정(Global Constraints 순서) →`saveBlob`.
    - 진행 중에는 비활성 + "다운로드 중…"이다. 422 `EXPORT_TOO_LARGE`와 그 밖의 실패 문구는 Global Constraints대로이고, 다음 클릭 때 지운다.
  - 테스트는 jsdom에 없는 `URL.createObjectURL`/`revokeObjectURL`을 테스트 파일에서 정의하고 `HTMLAnchorElement.prototype.click`을 spy한다. `http`·`httpBlob`은 mock하지 않는다(MSW).
